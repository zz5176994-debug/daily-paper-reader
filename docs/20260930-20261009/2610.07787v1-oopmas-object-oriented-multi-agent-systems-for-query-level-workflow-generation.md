## 摘要
由大语言模型驱动的多智能体系统（MAS）在代码生成、数学推理和问答等任务中展现出强大性能。然而，现有的自动化多智能体系统设计方法大多在任务层面运行，为每个基准生成单一固定工作流，并统一应用于所有查询。这一假设在实际条件下并不成立。查询难度在同一任务内差异很大，且真实工作负载混合了异构任务类型。我们提出OOPMAS，一个免训练框架，能够在单个查询粒度上同时生成智能体集合和协调工作流。智能体被表示为具有专属角色、工具和持久状态的面向对象类定义，工作流则表示为在这些智能体对象上执行的主函数。动态技能库在优化轮次中从执行反馈中积累结构化经验，从而在无需任何梯度更新或微调的情况下实现上下文内改进。在涵盖代码、数学和问答的混合任务基准上，OOPMAS达到了89.6%的准确率，比最强基线高出18.1个百分点。跨四个大语言模型骨干的模型替换研究表明其性能随模型增强而一致提升，使用最强模型时准确率达到92.4%。

## Abstract
Multi-agent systems (MAS) powered by large language models have shown strong performance across code generation, mathematical reasoning, and question answering. However, existing methods for automating MAS design mostly operate at the task level, producing a single fixed workflow per benchmark that is applied uniformly to all queries. This assumption fails under realistic conditions. Query difficulty varies widely within a task, and real-world workloads mix heterogeneous task types. We introduce OOPMAS, a training-free framework that generates both the agent set and the coordination workflow at the granularity of individual queries. Agents are represented as object-oriented class definitions with dedicated roles, tools, and persistent state, and workflows are expressed as executable main functions over these agent objects. A dynamic skill library accumulates structured lessons from execution feedback across optimization rounds, enabling in-context improvement without any gradient updates or fine-tuning. On a mixed-task benchmark of queries spanning code, math, and QA, OOPMAS achieves 89.6% accuracy, outperforming the strongest baseline by 18.1 percentage points. A model-swap study across four LLM backbones shows consistent scaling, reaching 92.4% with the strongest model.

## 1. 论文的核心问题与整体含义

- 现有基于大语言模型的多智能体系统（MAS）虽在代码、数学、问答等任务上表现优异，但其自动化设计方法大多停留在**任务级**：为每个基准/任务生成**单一固定工作流**，并统一应用于该任务下的所有查询。
- 这种任务级假设在真实部署中不成立：
  - **查询难度差异大**：同一任务内简单查询与复杂查询需要不同复杂度的工作流。
  - **工作负载混合异构**：真实查询流往往混合代码、数学、问答等多种类型，且比例不可预测；单一工作流只能覆盖其原生领域，无法处理完整混合分布。
- 另外，现有方法大多在**固定智能体池**上搜索工作流，限制了可达解空间；如果池中缺少特定领域专家，任何工作流都无法产生最优解。
- OOPMAS 的核心思想是：**将 MAS 生成视为查询级优化问题**，为每个查询动态生成智能体集合与协调工作流，从而适应异构任务分布和难度差异。

## 2. 论文提出的方法论

- **问题形式化**：
  - 一个查询 \(q\) 的多智能体系统定义为 \(S_q=(A_q,W_q)\)，其中 \(A_q=\{a_1,\dots,a_n\}\) 是智能体集合，\(W_q\) 是可执行工作流。
  - 每个智能体 \(a_i=(p_i,T_i,m_i(h_i),s_i)\) 包含角色提示 \(p_i\)、工具集 \(T_i\)、骨干模型及超参数 \(m_i(h_i)\)、持久状态 \(s_i\)。
  - 优化目标为：\(S^*_q=\arg\max_{S_q\in S}\text{Score}(S_q,q)\)，其中搜索空间同时包含智能体组成和工作流拓扑。
- **动态智能体生成**：
  - 智能体以**面向对象（OOP）类**表示：属性编码角色、模型配置、状态；方法暴露工具集和预定义任务。
  - 首先由元智能体 \(M_{agent}\) 基于验证查询集合生成共享智能体池 \(\bar A\)（单次调用）。
  - 然后对每个查询执行**覆盖验证**：检查共享池是否满足该查询所需能力，若不足则生成额外专家智能体并合并为查询特定集合 \(A_{q_i}\)。
- **工作流生成与优化**：
  - 元智能体 \(M_{workflow}\) 接收查询 \(q\)、智能体集合 \(A_q\) 和技能库 \(K\)，生成可执行的 `main` 函数；该函数导入智能体类、调用接口、执行工具并组合最终答案。
  - 工作流经过轻量静态检查（语法、入口点、是否调用 `agent.run`），失败则带错误信息重生成，最多 \(K\) 次修复。
  - 工作流在独立子进程中运行，并由任务特定函数评分。
  - **技能库 \(K\)** 是训练无关优化的核心：存储结构化 `FailureRecord` 和 `FixRecord`，包括轮级分数轨迹、崩溃模式、成功根因/修复对、失败修复尝试。每轮后诊断失败，提炼可复用技能并注入下一轮工作流生成。
- **算法流程**（两阶段）：
  1. 阶段一：生成共享智能体池 → 逐查询覆盖验证/增强。
  2. 阶段二：初始化技能库为空 → 多轮并行生成工作流、执行评分、诊断修复、更新技能库 → 输出每查询最优工作流。
- **训练无关性**：整个流水线不涉及梯度更新、蒸馏或微调，仅通过提示中的技能库实现上下文内改进。

## 3. 实验设计

- **数据集与基准**：
  - **Mixed benchmark**：120 个查询，来自六个标准来源：
    - 代码 40 个：HumanEval、MBPP；
    - 数学 40 个：MATH、GSM8K；
    - 问答 40 个：HotpotQA、DROP。
  - **Hard Mixed benchmark**：180 个竞赛级查询：
    - 数学 60 个：AIME 2025/2026；
    - 代码 60 个：LiveCodeBench、CodeContests；
    - 问答 60 个：GPQA Diamond。
  - 这些基准强制方法在**同一批次内处理异构任务类型和输出格式**。
- **对比方法**：
  - AFlow：基于 MCTS 优化代码表示工作流；
  - ADAS：元智能体迭代编程并归档智能体设计；
  - MaAS：多智能体超网搜索；
  - MetaAgent：基于有限状态机自动构建多智能体系统。
  - 所有基线使用 GPT-5 作为 worker 模型，接收相同的混合查询批次。
- **评估指标**：
  - 代码任务：pass@1（HumanEval、MBPP、LiveCodeBench、CodeContests）；
  - 数学任务：solve rate（MATH、GSM8K、AIME）；
  - 问答任务：F1（HotpotQA、DROP）、准确率（GPQA 多选）。
- **实现细节**：
  - 元智能体和 worker 模型均为 GPT-5（除非说明）；
  - Mixed 运行 \(R=5\) 轮优化，Hard Mixed 运行 \(R=3\) 轮；
  - 并发 30，每查询最多 7 个智能体；
  - 报告最高分数（动态技能库开或关）。

## 6. 论文的主要结论与发现

- OOPMAS 在 **Mixed** 基准上达到 **89.6%** 总体准确率，比最强基线 ADAS 的 71.5% 高出 **18.1 个百分点**。
- 在 **Hard Mixed** 基准上达到 **90.8%**，比 ADAS 的 72.3% 高出 **18.5 个百分点**，说明查询级生成在更困难的问题分布上仍能泛化。
- 任务级基线呈现典型失败模式：
  - AFlow 的单一工作流在代码上得 90%，但数学和问答为 0%，整体仅 30%；
  - MaAS 正相反，数学尚可但代码接近 0%；
  - ADAS 和 MetaAgent 因归档异构解决方案而更均衡，但仍大幅落后。
- OOPMAS 的按查询生成使简单问题仅需单专家调用，复杂问题自动获得包含规划者、审查者和迭代测试循环的多智能体流水线。
- 模型替换研究表明：OOPMAS 从 GPT-4.1 的 72.5% 一致提升到 GPT-5.2 的 92.4%；但弱模型 GPT-5-nano 上，AFlow 的固定 MCTS 脚手架更稳健（65.4% vs 51.0%），说明动态代码合成依赖强元智能体。
- 成本上，OOPMAS 花费更高但获得了在困难条件下保持准确率的鲁棒性，且可按查询选择性部署。

## 7. 优点

- **查询级联合生成**：同时生成智能体集合和工作流，扩展了搜索空间（从仅工作流搜索到联合智能体-工作流搜索），能适应异构任务分布和难度差异。
- **训练无关**：完全无需强化学习、蒸馏或微调，通过技能库的上下文记忆实现跨轮改进，部署门槛低。
- **面向对象智能体表示**：自然封装角色、工具和持久状态；支持灵活的对象交互；OOP 代码在 LLM 预训练语料中常见，生成更可靠。
- **基准设计贴近真实部署**：Mixed 与 Hard Mixed 基准包含多领域、多输出格式和竞赛级难度，能暴露任务级方法的隐藏失败模式。
- **可扩展性好**：模型替换实验显示性能随骨干模型能力平滑提升，无需修改系统。
- **鲁棒性**：即使移除技能库、覆盖验证等组件，OOPMAS 仍显著优于所有基线。

## 8. 不足与局限

- **依赖强元智能体**：当骨干模型较弱时，按查询合成智能体类和工作流可能不可靠，固定脚手架（如 AFlow）反而更稳健。
- **技能库不跨部署持久化**：当前技能库是运行本地的，仅在单

次运行内有效，无法跨任务或跨部署累积经验；作者也承认这限制了技能库的长期复用价值。

- **成本与延迟仍偏高**：Hard Mixed 基准上每查询约 $1.50，且多次生成、执行、修复会带来较高的端到端延迟；对大规模在线查询流不够友好。
- **混合基准规模有限**：Mixed 仅 120 个查询、Hard Mixed 仅 180 个查询，且来源固定，可能不足以覆盖真实环境中更长的任务分布尾部和突发类型。
- **评估指标混合口径**：代码 pass@1、数学 solve rate、问答 F1/accuracy 被合并为总体准确率，但论文未明确统一加权方式，可能模糊不同任务类型上的具体表现差异。
- **安全与沙箱问题未深入讨论**：OOPMAS 动态生成并执行工作流代码，若查询包含恶意指令或工具调用设计不当，可能带来代码执行风险；论文没有详细说明隔离机制、权限控制或防注入策略。
- **技能库可能积累噪声**：失败修复记录直接注入提示，如果诊断错误或根因归因不准，可能误导后续工作流生成；当前缺少过滤、置信度或冲突消解机制。
- **部分消融结论有限**：在 Mixed 基准上技能相关组件移除后波动较小，说明主要收益可能来自查询级联合生成本身，而非训练无关优化组件；这在一定程度上削弱了技能库贡献的独立说服力。
- **与任务级基线的比较存在构象差异**：任务级方法原本为单一任务优化，在混合批次中天然处于劣势；论文借此揭示部署缺陷是合理的，但该设置并不能说明 OOPMAS 在单一任务上也一定优于专用固定工作流。

## 9. 总结与启示

OOPMAS 将多智能体系统的自动生成从任务级推进到查询级，通过面向对象智能体类、动态工作流合成和训练无关技能库，在混合难度基准上显著超越任务级方法。其核心启示是：真实部署中的查询分布高度异质，按查询联合优化智能体组成与工作流，比固定工作流更能保持鲁棒性；同时，训练无关的上下文技能库可以在不进行梯度更新的情况下逐步改进系统。但该方法依赖强骨干模型、成本较高，且技能库不跨部署持久化。未来工作可探索轻量级元策略、跨任务技能蒸馏、安全执行沙箱和在线学习机制，以进一步缩小与真实系统部署要求之间的差距。
