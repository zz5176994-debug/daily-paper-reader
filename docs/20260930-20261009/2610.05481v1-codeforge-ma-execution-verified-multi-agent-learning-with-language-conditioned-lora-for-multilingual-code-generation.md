## 摘要
用于代码生成的大型语言模型在执行、多语言覆盖和污染控制方面常常表现不佳，尤其是在骨干网络被冻结的约束下。我们提出了 CodeForge-MA，这是一个统一框架，通过多智能体数据锻造、执行验证的强化指令微调以及语言条件 LoRA 适配器混合来改进代码合成。四个专用智能体——Composer、Reviewer、Executor 和 Curator——迭代地优化指令-代码对，用测试验证它们，并过滤重复项和基准泄漏。在训练过程中，我们将掩码监督微调与测试驱动的强化目标相结合，使生成结果与可执行正确性对齐。对于较大的模型，我们在低秩适配器上使用稀疏专家路由，以改善跨语言迁移，同时在推理时保持基座模型不变。实验表明，联合的数据、目标和适配器设计在多种编程语言上带来了稳健的增益。

## Abstract
Large language models for code generation often fail on execution, multilingual coverage, and contamination control, especially under frozen backbone constraints. We present CodeForge-MA, a unified framework that improves code synthesis through a multi-agent data forge, execution verified reinforced instruction tuning, and a language conditioned mixture of LoRA adapters. Four specialized agents, Composer, Reviewer, Executor, and Curator, iteratively refine instruction code pairs, validate them with tests, and filter duplicates and benchmark leakage. During training, we combine masked supervised fine tuning with a test driven reinforcement objective to align generations with executable correctness. For the larger model, we use sparse expert routing over low rank adapters to improve cross language transfer while keeping the base model unchanged at inference. Experiments show that joint data, objective, and adapter design yields robust gains across programming languages.

## 二、方法论

### 1. 总体框架

CodeForge-MA 建立在 Qwen-1.8B（初赛）和 Qwen-72B（决赛）两个解码器 Transformer 骨干之上，包含三个核心组件：

- **多智能体数据锻造（Multi-Agent Data Forge）**
- **执行验证强化指令微调（Execution-Verified Reinforced Instruction Tuning, EV-RIT）**
- **语言条件 LoRA 混合适配（Language-Conditioned Mixture-of-LoRA, LC-MoLoRA）**

### 2. 多智能体数据锻造

由四个专用 LLM 代理组成闭环（Reflexion 风格）：

| 代理 | 功能 |
|------|------|
| Composer | 根据种子生成候选指令-代码对 |
| Reviewer | 对风格、正确性、教学价值评分 |
| Executor | 在沙箱中编译并运行代码，给出通过/失败 |
| Curator | 全局去重与基准污染过滤 |

- **接受条件**：样本只有在执行通过（π=1）、质量分不低于 0.75、且修订次数不超过 3 时才会被保留。
- **Reviewer 自一致性**：对同一对采样 5 次评分取平均，以降低评审噪声。
- **失败样本回流**：若未通过，将 Reviewer 意见和 Executor 错误回溯拼接到提示中，重新生成，从而减少编译错误、缺失导入、函数签名错误等问题。
- **语言平衡采样**：引入温度参数 α=0.3 对语言分布进行平滑，避免 Python 样本占比超过 70%。
- **去重与去污染**：使用 MinHash LSH 计算 5-gram Jaccard 相似度，相似度超过 0.8 或与 HumanEval / HumanEvalFix / MBPP 提示重复的样本被剔除。

### 3. 执行验证强化指令微调（EV-RIT）

- **掩码监督损失**：仅对 assistant 回合的 token 计算交叉熵，防止模型只复制 docstring 而忽略代码正文。
- **执行奖励**：对采样生成的代码运行单元测试，奖励为**通过测试的比例**。
- **PPO 风格代理目标**：使用裁剪的重要性采样比优化奖励，并加入 KL 惩罚（β=0.02），防止模型利用测试漏洞产生奖励黑客行为。
- **Warm-up 调度**：在训练前 500 步只使用监督损失，之后逐步引入强化信号（1000 步内从 0 升至 0.3），避免在策略尚未稳定时引入噪声奖励。
- **语言反频率加权**：不同语言样本按数量的 -0.5 次方加权，缓解多语言不均衡。

### 4. 语言条件 LoRA 混合适配（LC-MoLoRA）

主要针对 Qwen-72B 决赛阶段，因全量微调不可行：

- 在注意力矩阵（Q/K/V/O）上添加 6 个低秩 LoRA 专家（秩 r=32，缩放 α=64）。
- **路由器**：根据提示的 mean-pooled 表征计算专家 logits，采用 **top-2 稀疏门控**。
- **负载均衡正则**：防止专家坍缩，确保每个专家在批次中都得到充分使用。
- **语言身份先验**：使用软目标（非 one-hot）将专家与语言族绑定，促进 C++ 和 Rust 等相关语言之间的知识共享。
- 所有可训练参数仅包括 LoRA 专家和路由器，**不足 72B 骨干参数的 1%**；推理时骨干完全冻结，仅增加 O(dE) 的路由开销。

### 5. 提示工程与数据预处理

- **角色专门化 ChatML 模板**：四个代理使用不同的系统提示，强制输出 JSON 格式，避免将解释混入代码块。
- **Chain-of-Repair**：针对修复任务，模型先生成故障定位、修复理由、修复代码三元组；评估时仅取第三部分。
- **数据过滤**：使用语言专用静态检查器（Python ast、JS acorn、Java javac、Go go vet、C++ clang、Rust rustc）过滤语法错误样本，并结合文档串、复杂度、困惑度进行语义过滤。
- **打包与 EOS 统一**：贪心序列打包至 2048 token，统一 EOS 为 ChatML 的 `<|im_end|>`，避免生成不终止或截断。

## 六、主要结论与发现

- **性能提升**：
  - CodeForge-Qwen-1.8B 在所有指标上超越同级及部分更大基线。
  - CodeForge-Qwen-72B 在 pass@1 达到 54.8%，超过 DeepSeek-Coder-33B-Instruct 的 51.2% 和 CodeLlama-70B-Instruct 的 49.5%，且仅更新不到 1% 的骨干参数。
- **消融结论**：
  - **多智能体数据锻造**是最大单一贡献：移除后 pass@1 从 31.0% 降至 21.9%。
  - **执行验证 RL** 和 **LC-MoLoRA** 分别带来约 2.6% 和 1.9% 的 pass@1 增益。
  - **污染过滤**虽然会降低训练集指标，但能恢复真实泛化能力。
  - **平衡语言采样**对跨语言稳定性（BMPS）至关重要。
  - **损失掩码**缺失会明显拖累性能（26.7% vs 31.0%）。
- **核心思想验证**：在骨干冻结条件下，从数据质量、奖励信号和参数高效适配三方面联合优化

- **超参数敏感性未充分讨论**：温度参数 α=0.3、相似度阈值 0.8、质量分阈值 0.75、KL 惩罚 β=0.02、RL 权重上限 0.3、LoRA 秩与专家数量等关键超参数均未给出敏感性分析或调参依据，读者难以判断这些值是否仅对当前比赛设置有效。
