## 摘要
大语言模型（LLM）已逐步发展成为自主智能体的核心。基于这一进展，基于大语言模型的多智能体系统（MAS）将多个智能体协调为一个协同团队，以完成超出单个智能体能力的复杂任务。此类系统的有效性不仅取决于智能体本身，还取决于协作机制的设计与组织方式。值得注意的是，现实世界中的协作通常是部分可观测的：由于物理或隐私相关约束，每个智能体只能获取环境的部分信息。然而，许多现有多智能体基准测试假设全局可观测，对系统评估协作机制的支持有限。为弥补这一不足，我们提出了 MASBench，一个在部分可观测约束下设计的多智能体协作基准测试。它被组织为三个递进的任务类别：推理、调度和博弈。通过这一结构，我们逐步评估三种有代表性的协作机制：协议、记忆和路由。MASBench 进一步提供了确定性的评估指标，包括性能得分、通信成本和成本效益，以刻画协作效果与通信开销。在多种大语言模型基座和机制配置上的实验为有效的多智能体系统设计提供了经验指导。代码见：https://github.com/BUPT-GAMMA/MASBench

## Abstract
Large language models (LLMs) have progressively evolved into the core of autonomous agents. Building on this progress, LLM-based multi-agent systems (MAS) coordinate multiple agents into a synergistic team to accomplish complex tasks that exceed the capabilities of individual agents. The effectiveness of such systems depends not only on the agents themselves, but also on how collaboration mechanisms are designed and organized. Note that real-world collaboration is typically partially observable, where each agent can only access partial information about the environment due to physical or privacy-related constraints. However, many existing multi-agent benchmarks assume global observability, and leave limited support for systematically evaluating collaboration mechanisms. To bridge this gap, we introduce MASBench, a multi-agent collaboration benchmark designed under partially observable constraints. It is organized into three progressive task categories: Reasoning, Scheduling, and Game. Through this structure, we progressively evaluate three representative collaboration mechanisms: Protocol, Memory, and Routing. MASBench further provides deterministic evaluation metrics, including performance score, communication cost, and cost effectiveness, to characterize both collaboration outcomes and communication overhead. Experiments across diverse LLM backbones and mechanism configurations offer empirical guidance for effective MAS design. Code is available at: https://github.com/BUPT-GAMMA/MASBench

## 2. 论文提出的方法论

### 2.1 问题形式化

- 多智能体系统形式化为三元组 **⟨G, A, E⟩**：总体目标 G、智能体集合 A、共享环境 E。
- 每个智能体 \(A_i\) 定义为 **⟨O_i, m_i, M_i, D_i, C_i⟩**：
  - \(O_i\)：观测函数，感知当前环境并接收上一轮发给自己的消息；
  - \(m_i\)：智能体记忆；
  - \(M_i\)：记忆管理函数；
  - \(D_i\)：决策函数（与环境交互）；
  - \(C_i\)：通信函数（与其他智能体交互）。
- **部分可观测**：每个智能体的观测函数只能感知全局状态的局部视图，并仅能接收发给自己的消息。

### 2.2 三种关键协作机制

- **Memory（记忆）**：通过动态记录、总结和维持历史观测与交互，支撑长期协作的一致性。
- **Routing（路由）**：决定通信拓扑，即“谁与谁、何时通信”，促进更有效、及时的信息交换。
- **Protocol（协议）**：通过消息模式和交互规则规范智能体之间的通信与组织，减少歧义、提升稳定性。

### 2.3 三类递进任务设计

| 任务 | 智能体数 | 实例数 | 侧重机制 | 关键设计 |
|------|----------|--------|----------|----------|
| **Reasoning** | 2 | 300（200/100） | Protocol | 将 HotpotQA 多跳证据链拆分给两个智能体，各自只能看到部分证据，必须多轮对话交换线索并达成共识。按支持事实数、上下文长度、答案长度划分 Simple/Complex。 |
| **Scheduling** | 5 | 200（100/100） | Memory & Protocol | 隐私受限的会议时间协调：每个智能体只能访问自己的日历，禁止公开完整日程；需协商出一个所有人可行的 20 分钟连续窗口。困难度由可行窗口数 \(N_{\text{solution}}\) 控制（Simple：4–5 个；Complex：2–3 个）。通信为广播式聊天，不含路由。 |
| **Game** | 4–8 | 100（50/50） | Memory, Routing & Protocol | 合作网格世界资源收集任务（Dec-POMDP 风格）：智能体在局部观测下探索地图、收集资源并运送到仓库。每个智能体只能携带一种资源类型且有容量限制。简单地图 15×15，复杂地图 18×18。通信为点对点。 |

### 2.4 评估指标

- **Performance Score（性能得分）**：归一化到 [0,100]。
  - Reasoning：预测答案与参考答案的词级 F1 × 100；
  - Scheduling：成功率 × 100（只有输出窗口对所有智能体可行才算成功）；
  - Game：最终收集资源得分 / 地图参考得分 × 100。
- **Communication Cost（通信成本）**：代理间消息生成的总 token 数，**不包括**各智能体本地推理 token。
- **Communication Efficiency（通信效率）**：每 1000 通信 token 所获得的性能得分，综合效果与开销。

## 3. 实验设计

### 3.1 LLM 骨干模型

- **覆盖模型**：Llama-3.1-8B、GPT-5-nano、Gemini-2.5-Flash-Lite、DeepSeek-v3.2、Qwen-Plus。
- 由于 Llama-3.1-8B 在 Scheduling 和 Game 中失败率过高，仅在 Reasoning 类别中评估；其余四个模型用于全部三类任务。

### 3.2 机制配置

- **Reasoning**：
  - Base（自由对话）
  - Protocol（类型化消息：`<Q>` 信息请求、`<R>` 证据共享、`<A>` 最终答案）
- **Scheduling**：
  - Base（自然语言协商）
  - Memory（结构化可用性白名单 + 跨轮候选/拒绝槽位记忆）
  - Memory + Protocol（多阶段协议：粗搜索 → 候选提案 → 投票）
- **Game**：
  - Base（禁用通信，仅局部观测）
  - Memory（存储已发现的世界状态）
  - Memory + Random Routing（随机选择接收者）
  - Memory + Gate Routing（先决定是否通信，再选接收者）
  - Memory + Random + Protocol
  - Memory + Gate + Protocol（协议约束消息为 STATE/OBS/MSG 结构化格式）

### 3.3 框架级对比

- 在共享的 30% 子集上评估 **CAMEL** 和 **AgentVerse** 两种通用多智能体框架，并与 MASBench 的参考系统（各任务最优机制配置）对比，验证基准作为通用测试平台的适用性。

- 逐轮得分演化、消息长度分布、贡献熵（Contribution Entropy）、跨轮记忆消融、错误类型分析（每个任务 40 个采样失败案例）。

## 6. 论文的主要结论与发现

- **基座模型能力决定性**：Qwen-Plus 在三个任务中 Score 最高，表明强基座能力是部分可观测条件下达到高效用的决定性因素；但高 Score 不一定带来高 Eff，有时其他模型在效率上更优。
- **机制增益跨模型、跨任务一致**：
  - Reasoning：Protocol 普遍提升协作效率，Score 温和提升（+1.5% ~ +28.4%），通信 token 大幅下降（45.0% ~ 72.7%），Eff 提升 2.0× ~ 4.2×。
  - Scheduling：Memory 显著改善成功率；Protocol 进一步提升成功率和效率；跨轮记忆消融显示状态保留本身即可带来收益。
  - Game：Memory 显著改善长程协调；Gate 路由优于 Random（Score 提升 2.35–6.57 分，Token 降低 28.0%–35.6%）；加入 Protocol 后 Eff 提升 1.12×–1.91×，但 Random+Protocol 仍不如 Gate，说明路由质量至关重要。
- **框架级**：通用编排框架在部分可观测约束下不能自动适应信息不对称，性能差距随协作需求增加而扩大；AgentVerse 通常通信更紧凑、在多数 Scheduling 任务中表现更好，CAMEL 在多数 Game 任务中更强。
- **进一步分析**：Protocol 能显著缩短消息长度并降低方差；Memory 加速调度协商；Game 中最佳配置为 Memory+Gate+Protocol，协议能将记忆有效转化为低歧义协调。
