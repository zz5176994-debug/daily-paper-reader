## 摘要
智能体编排配置指定用于解决任务的角色、指令、工具和通信结构，合适的配置取决于具体查询。由于每个设计选择的价值只有通过执行才能观察到，为每个查询定制配置一直需要在推理时执行备选方案或进行昂贵的人工设计。我们提出 SHIFT，它将执行移出按查询搜索循环。一个本地 LLM 架构师从搜索中学习关于构建配置动作的策略，并学习一个价值函数，该函数根据已测量的执行情况预测在准确率与执行成本之间权衡的效用。对于每个查询，蒙特卡洛树搜索利用这些预测来构建配置。在六个基准共 9,193 个任务中，涵盖从数学到文档和通用助手任务，使用 Gemini 3.5 Flash 执行器，SHIFT 取得了最高的平均准确率（约 80%），优于 17 个基线，这些基线涵盖提示、提示优化和工作流搜索，并且比最强基线高出 7.2 个百分点。SHIFT 的一种更廉价模式也取得了高于所有基线的平均准确率，同时执行 token 使用量比最强基线少 32%。我们进一步表明，联合选择结构、指令和工具比仅选择指令或仅选择工具最多高出 9.1 个百分点，并且学习到的价值选择能够从候选池中识别出准确率更高且执行成本更低的配置。

## Abstract
Agent harnesses specify the roles, instructions, tools, and communication structure used to solve a task, and the right harness depends on the query. Because the value of each design choice is observable only through execution, tailoring a harness to each query has required either executing alternatives at inference time or costly manual design. We introduce SHIFT, which moves execution out of the per-query search loop. A local LLM architect learns a policy over harness-building actions from search, and a value function that predicts, from measured executions, a utility balancing accuracy against execution cost. For each query, Monte Carlo tree search uses these predictions to construct a harness. Across 9,193 tasks in six benchmarks, from math to document and general-assistant tasks, with a Gemini 3.5 Flash executor, SHIFT attains the highest mean accuracy, about 80%, outperforming 17 baselines that span prompting, prompt optimization, and workflow search, and exceeding the strongest baseline by 7.2 percentage points. A cheaper mode of SHIFT also attains a higher mean accuracy than every baseline while using 32% fewer execution tokens than the strongest baseline. We further show that choosing structure, instructions, and tools jointly beats choosing only instructions or only tools by up to 9.1 percentage points, and that learned value selection identifies more accurate harnesses with lower execution cost from candidate pools.

## 1. 论文的核心问题与整体含义

- **核心问题**：多智能体系统（称为 harness）由角色、指令、工具和通信结构组成，其最优设计高度依赖具体查询。但每个设计选择的价值只有通过实际执行才能观察，因此按查询定制 harness 要么需要在推理时执行大量候选方案（成本高），要么依赖昂贵的人工设计。
- **研究动机**：现有方法中，工作流优化离线搜索可复用结构、提示优化在固定程序内调整指令、查询自适应控制器生成工作流或路由，但都没有在推理时无执行地比较多个交互设计选择。
- **整体含义**：论文提出 SHIFT（Searching Harnesses In Forward-pass Trees），将执行移出按查询搜索循环，通过本地小模型架构师预测 harness 效用，用蒙特卡洛树搜索为每个查询构建最优 harness，从而在准确率与执行成本之间取得平衡。

## 2. 论文提出的方法论

- **核心思想**：将 harness 设计形式化为树搜索问题，由本地 LLM 架构师学习策略和价值函数，在推理时仅用架构师推理指导 MCTS，不执行候选 harness，最终只执行选中的 harness。
- **可执行图表示**：
  - Harness 表示为有向图 \(G=(V,E)\)，节点是 agent（含角色、指令列表、工具权限），边传递输出；支持反馈边。
  - 每个中间图均可执行，因此搜索可以比较部分和完整设计。
  - 动作包括：添加 agent、添加反馈边、追加指令、授予工具、停止构建；共 40 个动作的词汇表。
- **策略–价值架构师**：
  - 骨干为 Gemma 4 E2B（约 2B 参数），仅训练 LoRA 适配器和两个线性头（策略头、价值头）。
  - 输入：查询、可用工具、可行动作、当前图的文本序列化。
  - 输出：可行动作上的概率分布 \(\pi_\theta(a|q,s)\)，以及标量效用预测 \(V_\theta(q,s)\in(0,1)\)。
- **蒙特卡洛树搜索（MCTS）**：
  - 从最小 harness（单个无工具 Coder）开始。
  - 每轮迭代：根据 PUCT 公式（式 3）选择、扩展、用价值头评分叶节点、回传统计量。
  - 并行搜索采用虚拟损失避免重复路径；执行器在搜索循环内从不被调用。
  - 两种推理模式：SHIFT-search 执行访问最多路径末端；SHIFT-value 执行预测效用最高的候选，若效用低则追加搜索。
- **训练目标**：
  - 成本感知奖励 \(R=\alpha u - b - \sum\gamma_x r_x\)，其中 \(u\) 为任务成功分数，惩罚项覆盖执行 token、延迟、超时、工具数、agent 数；奖励被裁剪并重缩放为 \([0,1]\) 的效用 \(z\)。
  - 策略目标：匹配搜索访问分布（交叉熵 + 熵正则）。
  - 价值目标：二元交叉熵拟合测量效用。
  - 排名损失：同一查询下不同 harness 的效用排序，使用边际 hinge 损失。
  - 在线训练：每个训练查询运行搜索并执行多个候选，加入优先重放缓冲区；每轮结束时进行排名回放。

## 6. 论文的主要结论与发现

- **总体性能**：SHIFT-search 平均准确率 79.9%，比最强基线 Trace（72.7%）高 7.2 个百分点；SHIFT-value 平均准确率 74.5%，高于所有基线，且执行 token 比 Trace 少 32%。
- **增益来源**：主要来自长时程、工具密集的 OfficeQA（+30.0%）和 GAIA（+15.0%）；在短时程任务上接近领先基线。
- **联合优化必要性**：同时选择结构、指令和工具比仅选择指令或仅选择工具最多高 9.1 个百分点。
- **搜索与成本权衡**：搜索在保持与 greedy 相近准确率的同时降低了约 30% 执行 token；SHIFT-value 通过价值选择进一步降低成本。
- **价值函数的有效性**：学习到的价值头能从候选池中选出更准确且更便宜的 harness，且选择效果随候选数增加而提升。

## 7. 优点

- **创新性**：首次在推理时用本地小模型预测效用并指导 MCTS 构建 harness，无需执行候选方案，显著降低按查询定制的成本。
- **统一表示**：用可执行图统一单 agent、多 agent、带验证回路的流程，使一个搜索过程覆盖多种结构。
- **成本感知**：奖励函数显式平衡准确率与执行 token、延迟、工具/agent 数量，使价值头学到“最便宜且能解决任务的 harness”。
- **实验严谨**：与 17 个基线在同一执行器上公平比较，提供置信区间、问题级配对检验、成本 Pareto 前沿和多轮运行结果。
- **可迁移性**：展示从 GSM8K 迁移到 MATH-500 的能力，且增益集中在难题上。
- **工程实现高效**：默认搜索在单块 H100 上不到 1 秒，批处理叶子评估和虚拟损失提高了搜索效率。
